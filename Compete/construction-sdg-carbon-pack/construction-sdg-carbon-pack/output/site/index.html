Provenance & caveats

Where the field names come from

Field names on every page are validated against /tmp/qwenwork/schema.json — the machine-parsed form of the source ERD file. That parse yields 45 tables, 320 columns and 84 foreign keys across 7 phase groups (core, d12, p34, p5, p67, sdg, cc). A column name may only appear on a page when it belongs to one of that frame's declared source tables; the build fails otherwise.

Known mismatch with the source labels

The source HTML describes itself in its own header as “47 tables · 6 phases”, but the schema array inside that same file parses to 45 tables across 7 phase keys. This demo follows the parsed data, not the label; the two-frame difference (plus “SDG layer” and “Carbon credit layer” being separate keys rather than one phase) is carried through the rail and the hub grouping.

Non-functional disclaimer

This is a visual-only static site. There are no scripts, no handlers, no data fetching and no state: filters, tabs, sort arrows, pagers and buttons are rendered as they would look, and the CSS-only interactions (hover, :target, radio tabs) exist to show states, not to implement behaviour. Values are plausible construction-project numbers, not real ones.

What was simplified

Charts that a wireframe drew as placeholders (S-curve, drawdown line, LTIFR trend, CO₂ grid-intensity) are drawn as static CSS / inline-SVG shapes over the same series. Panels the wireframe marked “derived, no table” are kept visibly labelled as derived.
