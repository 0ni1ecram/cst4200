Quality tests & NCR lifecycleframe 15

quality_test results drive the ncr state machine

Purpose. Conformance evidence. quality_test stores one measured result against an enumerated test_type ; a failed test raises an ncr whose state machine is ncr_status . The design target itself (e.g. f′c) is not a column on quality_test in this schema — the comparator comes from the spec reference.

Frame specification (from the wireframe pack)

Primary actions

  • log test result
  • auto-raise NCR on fail
  • assign disposition
  • schedule retest
  • close with evidence

Validation & business rules

  • A failed pass_fail must spawn exactly one open NCR before the next percent_complete tick (frame 13).
  • NCR close requires closed_date plus linked retest row; element bridge to asset handover rides on element_id (frame 18).
  • Tests are keyed to wbs / room / element so results roll into the O&M file.

Roles / states

  • CQE raises & closes; lab submits results; architect approves accept-as-is
  • no tests this week · NCR overdue · retest pending · hold on next pour
